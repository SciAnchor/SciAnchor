# 公开归档数据集获取

SPC 使用独立的 `spc.archive-dataset-record.v1` 表达 Zenodo 等公开归档记录，避免把归档版本、许可、文件 checksum 和 ZIP inventory 混入 GEO 的 `BiomedicalDatasetRecord`。

先读取机器能力边界：

```bash
spc dataset archive capabilities --output-format json
```

当前支持 `zenodo` record ID 与 `figshare` public article ID 的 inspect/download/远程 ZIP inventory。Figshare adapter 同时适用于 ACS 官方 Figshare Supporting Information，但不会把 SI ZIP 或其中 PDF 冒充论文正文；`resource_doi` 与 SI 自身 DOI 分开保存。当前尚不支持 `proteomexchange`、`iprox`、`pride` 和 `europe_pmc_supplementary`，调用这些来源稳定返回 `archive_source_capability_unsupported / capability_unsupported`，而不是 argparse invalid choice、`resource_not_found` 或隐式猜测其他命令。

归档 HTTP 不继承进程的 ambient system proxy，也不读取其他能力的代理配置。Figshare 官方 REST/CDN 若在直连出口返回 HTTP 403，且 `ARCHIVE_PROXY_MODE=proxy` 与 `ARCHIVE_PROXY` 已显式配置，SPC 会把同一笔 metadata、Range inventory 与下载事务切换到同一归档代理出口。终局的 `transport` 和 `transport_attempts` 只记录脱敏路由、状态码与触发原因，不记录代理地址或凭证；未配置合法回退时，403 稳定返回 `archive_repository_access_forbidden / access_blocked`，不泛化为 `network_error`。

只读检查：

```bash
spc dataset archive inspect --source zenodo --record 11387725 \
  --remote-inventory --output-dir <dir> --output-format json
```

`--remote-inventory` 只读取 ZIP EOCD、central directory 和不超过阈值的 JSON/TXT entry。任何返回 HTTP 200 的整包响应都会在读取正文前拒绝；只有 HTTP 206 和精确 `Content-Range` 才可继续。`manifest_ready=true` 仅说明来源元数据、文件清单和远程 inventory 已核验，不代表 payload 已下载。

ZIP central directory 与小条目解析是两个独立层次。中央目录核验成功后，单个 JSON/TXT 的编码或内容错误不会清空 inventory：小条目原始字节会以 SHA-256 和受控 raw 路径保存；JSON 仅接受严格 UTF-8（允许 BOM），TXT 不猜测本地编码。解码失败以 `archive_entry_decode_failed` 写入 `entry_errors` 和顶层 `warnings`，同时继续保持 `manifest_ready=true`。这类内容错误不得归类为网络错误。

`__MACOSX/`、`._*` AppleDouble 资源叉和 `.DS_Store` 会显式标记为 `packaging_artifact` 并跳过正文解析。`entry_type_counts` 不会再按其伪扩展名把资源叉计为科研 TXT 或 NIfTI；原始条目仍保留在 `entries` 与 `packaging_artifacts`，便于版本打包差异审计。

公开 API 能返回记录元数据但不暴露文件清单时，SPC 不会把记录误报为不存在。`restricted`、`embargoed` 或 `closed` 记录返回 `status=access_restricted`、`files_visible=false`、`access_requirement=authentication_required`，并保留公开的 record、DOI、标题、版本、许可和 access；此时 `manifest_ready=false`、`payload_ready=false`。SPC 不接受、保存或复用用户的 Zenodo 登录凭证。只有记录 API 返回 404 时，记录本身才归类为 `resource_not_found`。

Zenodo record 可能通过 HTTP 302 从 concept/别名记录解析到具体版本。终局同时保留兼容字段 `record`、`requested_record`、`resolved_record` 和脱敏的 `record_resolution[]`（只含状态及 record ID，不保存远程 URL）。若解析后的记录返回 HTTP 410/tombstone，稳定返回 `status=record_gone`、`error_code=archive_record_gone`、`error_class=record_withdrawn`，并保留公开的 removal date/reason/policy；这属于永久记录状态，不是 `network_error`。此时不会发起 Range 或 payload 请求，`manifest_ready=false`、`payload_ready=false`，失败终局仍原子写入 `archive_dataset_record.json`。

显式物化：

```bash
spc dataset archive download --source zenodo --record 11387725 \
  --file ReMIND2Reg_dataset.zip --resume --verify-checksum \
  --output-dir <dir> --output-format json --detach
```

下载使用同目录 `.part` 续传，字节数和来源 checksum 全部通过后才原子替换目标文件并令 `payload_ready=true`。stdout 和持久记录不保存代理认证、Cookie、签名查询参数或远程下载 URL。

正文流遇到 `IncompleteRead`、连接复位等可重试传输错误时，SPC 最多进行四次有界 Range 续传，并在终局记录 `stream_attempts` 与 `resumed_from_bytes`。若最终仍失败，同 source/record 且身份已核验的既有 manifest、remote inventory 和 warnings 会保留，只有 `payload_ready` 保持 false；失败不得把已经成立的 `manifest_ready` 降为 false。

同一 `output-dir` 的 inspect 与 download 共享一把有界跨进程写锁，并维护同一个 `archive_dataset_record.json`。download 在传输前和提交时重载既有记录；只有 `source + record + version + 全部文件 key/bytes/checksum` 完全一致时，才继承已经核验的 `remote_archives`、entry warnings 和 manifest summaries。任一身份字段不一致返回 `archive_state_identity_conflict`，不会下载文件或覆盖旧记录；并发事务超时返回 `archive_state_busy`。下载单个小文件只更新对应 materialization/download 事实，未下载的其他 payload 仍使 `payload_ready=false`，不得用保留的远程 inventory 冒充物理 payload 已就绪。
