# SPC 2.0 元数据调度与缓存架构

> 元数据 HTTP 只使用显式 `METADATA_PROXY`，不读取普通 PDF 的 `DOWNLOAD_PROXY`。HTTP 429、超时和 5xx 在调度器内部排队/冷却，不转换为业务 `not_found`。

## 1. 产品契约

调用方声明论文标识、查询条件和所需字段，不管理 API Key、429、冷却或缓存。一次可靠元数据操作只有四类终局：

1. 返回满足字段契约的数据；
2. 权威端点明确 404，返回 `resource_not_found`；
3. 认证拒绝、无效输入等永久错误；
4. 调用方取消。

429、连接中断、超时和 provider 5xx 是内部调度状态，不得转换成 `None`、空列表、`no_result` 或业务 404。可能长时间等待的命令使用 `--detach`，然后用 `spc job wait <job-id>` 读取统一终局；同步和 detached 复用同一业务内核。

## 2. 最小分层

| 层 | 职责 | 不负责 |
| --- | --- | --- |
| Source adapter | URL、参数、字段解析、权威 404 语义 | Key 轮转、通用缓存文件布局 |
| Provider scheduler | 配额租约、429 冷却、临时错误退避 | 论文字段融合 |
| Metadata cache | 版本化响应、TTL、负缓存、相同请求合并 | 判断论文全文成功 |
| Paper service | 多源身份与字段融合、业务错误 | 暴露 Key 或内部重试 |
| Job | 持久执行、wait、cancel 和统一公共结果 | 解析日志或组合第二套状态判断业务成功 |

S2 的多 Key 配额是 provider 特有能力；缓存和 single-flight 是 OpenAlex、S2、Crossref、Europe PMC/PubMed 等来源共享的基础设施。不得为每个来源复制缓存数据库或后台任务系统。

## 3. S2 Key 池

Key 由用户自行申请并配置（`SEMANTIC_SCHOLAR_API_KEY(S)`、`OPENALEX_API_KEY(S)`）；不配置时走匿名通道。S2 与 OpenAlex 共用 provider Key 状态库 `~/.spc/state/provider-keys.sqlite3`，可通过 `SPC_STATE_ROOT` 移到其他持久目录；不同 provider 的记录严格分区。

- 明文 Key 只从进程环境读取；SQLite 仅保存 SHA-256 指纹。
- SQLite `BEGIN IMMEDIATE` 原子分配每 Key 单在途租约，多进程共享。
- 每 Key 独立 `available_at`；429 只冷却当前 Key，并优先遵守 `Retry-After`。
- 租约有硬过期；进程崩溃后无需人工清锁。
- 401/非配额型 403 作为当前认证周期的永久拒绝停用对应 Key；24 小时后允许一次受控复核，不会伪装成限流或无结果。含 rate-limit/quota 证据的 403 仍按临时冷却处理。
- provider 5xx/网络错误使用共享指数退避；成功请求清除 provider 临时退避。
- 全部 Key 冷却时等待最早恢复并可响应任务取消，不向业务层返回 429。
- 有 Key 时不再经过单一 source 全局节流器；并发上限由 Key 租约保证。匿名通道仍串行节流。

`spc doctor` 默认只读取配置数量和池状态，不逐 Key 发请求。`--probe-semantic-scholar` 与 `--probe-openalex` 分别通过对应调度池验证一次实网请求，输出不得含 Key 指纹或预览。

## 4. 通用元数据缓存

缓存默认为 `~/.spc/cache/metadata.sqlite3`，可通过 `SPC_CACHE_ROOT` 或 `SPC_METADATA_CACHE_DB` 改变位置。

缓存键由以下部分组成：

```text
source + API version + operation + fields version + SHA-256(normalized identity/query)
```

规则：

- 正缓存必须有 source、存入时间、过期时间和字段 Schema 版本。
- 字段集或 API 版本变化后不得命中旧的不完整响应。
- 只有权威 404 可写短 TTL 负缓存；429、408、网络错误、5xx 和解析错误禁止写负缓存。
- 过期记录返回 `stale`，不会静默当作有效命中；是否允许 stale 必须由具体业务显式决定。
- 相同请求使用跨进程、可续期 single-flight 租约；持锁者再次检查缓存后才访问上游。
- 缓存记录损坏是明确本地状态错误，不能静默当作 miss 后放大上游流量。
- 缓存数据库不得位于源码、wheel、`site-packages` 或 Seed Pack 事实源目录。

本轮不把 S2 Key 逻辑泛化成所有 provider，也不一次性改写全部 source。后续按调用量和错误风险迁移到同一缓存/调度接口；每次迁移必须删除对应旧缓存键、吞异常和外层重试说明。

## 6. 验收门禁

- 全部 Key 429 后等待并恢复成功，业务层看不到 429/`None`。
- 两个进程不能同时租用同一 Key；异常退出后租约自动恢复。
- 同请求并发只访问上游一次；持有期间自动续租。
- 404 可短期负缓存；429、超时、5xx 不产生负缓存。
- 缓存 TTL、字段 Schema 变化和损坏记录均有确定行为。
- 取消释放 Key 与请求租约。
- stdout、stderr、事件、doctor、数据库和测试报告均无 Key、代理或签名 URL。
- `spc schema`、插件 Skill、CLI help 与代码保持一致。
