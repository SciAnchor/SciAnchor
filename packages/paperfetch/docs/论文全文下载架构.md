# SPC 2.0 论文全文下载架构

`paper lookup` 只查询元数据；`paper download` 获取并验证 PDF，默认继续 MinerU；`paper parse`
只解析本地 PDF，不绑定论文身份；`seed-pack enrich` 补齐已有记录文件。

## 合法路线

paperfetch 只使用合法、可公开获取的全文来源：

- 本地/全局缓存（`route=local`）；
- Europe PMC、PMC 等开放仓储；
- arXiv 等预印本服务；
- 出版社官方 API（需要用户自行配置对应 API Key，例如 `ELSEVIER_API_KEY`）；
- Unpaywall/OpenAlex 等给出的开放获取 PDF 链接（`route=public_http`）。

paperfetch 不包含机构图书馆、校园网或订阅代理访问，也不使用非官方镜像。没有合法开放副本时，
下载以稳定错误码失败，而不是降级到不可信来源。

`--route auto` 允许本安装中最佳的合法路线；`--route public` 只允许开放/公开路线。

## PDF 成功的定义

PDF 成功必须同时满足物理 `%PDF-`、非空字节、SHA-256、目标论文身份和原子落盘。PDF 成功但
MinerU 失败为 `partial`，继续返回 PDF。

下载结果保留：

```json
{"download":{"route":"europe_pmc","access":"public","identity_verified":true}}
```

`route` 只记录最终成功路线。缓存命中统一为 `route=local`、`access=local`。

候选 URL、代理、失败尝试、浏览器事件和进程回收进入显式 debug 记录，不进入默认结果。

## 浏览器辅助下载

部分开放获取页面需要真实浏览器渲染才能拿到 PDF。此能力需要安装可选依赖
`pip install -e ".[browser]"` 和正式版 Google Chrome。浏览器任务结束时必须回收全部进程。
页面明确出现复选框、CAPTCHA、MFA 或设备确认时立即返回 `unattended_auth_blocked`；SPC 不点击、
不绕过，也不调用挑战求解服务。

## 下载失败诊断

单篇失败只返回一个稳定 `error`：`code`、`message`、`stage` 和 `next`。`retryable`
仅在可稍后重试时出现。页面快照与浏览器细节只进入脱敏 audit。

网络类失败后运行 `spc doctor --probe-traffic-classes`：

- 代理端点不可达与 407 是已确认原因；
- 通路检查为 ok 只证明探针可达，不证明某篇论文可获取。

`spc validate download` 可用内置或自定义样本集连续验收下载质量与性能。
